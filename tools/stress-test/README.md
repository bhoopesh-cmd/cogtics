# Cogtics Stress Testing Tools

Comprehensive stress testing suite for the Cogtics platform, designed to test volume, concurrency, and system limits.

## Setup

### 1. Install Dependencies

```bash
cd tools/stress-test
npm install
```

### 2. Verify Infrastructure

Ensure all services are running:

```bash
docker-compose ps
```

Expected services:
- `postgres` (port 5432)
- `redis` (port 6379)
- `minio` (ports 9000, 9001)
- `api` (port 3000)
- `worker` (processing jobs)

### 3. Seed Test Data

```bash
cd ../..  # Back to project root
pnpm db:seed
```

This creates:
- Tenant: `tenant_01`
- Admin user: `user_01`
- Test data for contracts, customers, etc.

## Usage

### Quick Start - Run Single Test

```bash
# Small batch (50 PDFs, 5 concurrent)
npm run test:small

# Medium batch (100 PDFs, 10 concurrent)
npm run test:medium

# Large batch (500 PDFs, 25 concurrent)
npm run test:large

# Extra large (1000 PDFs, 50 concurrent)
npm run test:xlarge

# Stress test (2400 PDFs, 100 concurrent)
npm run test:stress
```

### Run All Tests Sequentially

```bash
npm run test:all
```

This runs small → medium → large → xlarge → generates report.

### Custom Test Parameters

```bash
npm run volume -- --batch=200 --concurrency=15
```

Parameters:
- `--batch=N` - Number of PDFs to upload (default: 50)
- `--concurrency=N` - Concurrent uploads (default: 5)

## Monitoring

### Real-time System Monitoring

Run monitoring in a separate terminal while tests are running:

```bash
npm run monitor
```

This will:
- Collect metrics every 1 second
- Display real-time stats (API/Worker memory, queue depth, DB size)
- Save to CSV on exit (Ctrl+C)

Output: `outputs/metrics-{timestamp}.csv`

### Metrics Collected

| Metric | Description |
|--------|-------------|
| `apiMemoryMB` | API container memory usage |
| `workerMemoryMB` | Worker container memory usage |
| `postgresConnections` | Active PostgreSQL connections |
| `redisMemoryMB` | Redis memory usage |
| `queueDepth` | BullMQ `upload.pdf.parse` queue depth |
| `dbSizeMB` | PostgreSQL database size |

## Generating Reports

After running tests, generate a comprehensive report:

```bash
npm run report
```

This generates:
- **JSON**: `outputs/volume-test-{timestamp}.json` - Raw data
- **Markdown**: `outputs/volume-test-{timestamp}.md` - Human-readable report
- **CSV**: `outputs/volume-test-{timestamp}.csv` - Time-series data for graphing

### Report Contents

- **Summary Table**: All test runs with key metrics
- **Detailed Results**: Per-test breakdown with threshold analysis
- **Breaking Points**: First batch size where thresholds were exceeded
- **Error Analysis**: Unique errors encountered

## Configuration

Edit `config/test-config.ts` to adjust:

- **Thresholds**: Performance and resource limits
- **Batch Configs**: Predefined test scenarios
- **API Settings**: URL, auth mode, tenant/user IDs

## Thresholds

| Metric | Threshold | Description |
|--------|-----------|-------------|
| Presigned URL | 500ms | API response time for URL generation |
| Job Enqueue | 200ms | Time to enqueue BullMQ job |
| Job Process | 10s | Worker processing time per PDF |
| End-to-end | 30s | Total time from upload to completion |
| API Memory | 1GB | API container memory limit |
| Worker Memory | 2GB | Worker container memory limit |
| Queue Depth | 1000 | Max pending jobs in queue |
| Error Rate | 5% | Max acceptable failure rate |

## Troubleshooting

### No PDFs Found

Ensure PDFs are generated:

```bash
cd tools/synthetic-data
python examples/generate_pdfs.py --input output/stress_test/data/contracts.json --output output/stress_test/pdfs
```

### API Connection Refused

Check API is running:

```bash
curl http://localhost:3000/health
```

### Database Connection Error

Check PostgreSQL:

```bash
psql "postgresql://cogtics:cogtics@localhost:5432/cogtics" -c "SELECT 1;"
```

### Worker Not Processing

Check worker logs:

```bash
docker-compose logs -f worker
```

Check Redis:

```bash
redis-cli ping
redis-cli llen "bull:upload.pdf.parse:wait"
```

## Architecture

```
┌─────────────┐
│ volume-test │ - Uploads PDFs concurrently
└──────┬──────┘
       │
       v
┌─────────────┐
│     API     │ - Generates presigned URLs
│             │ - Enqueues BullMQ jobs
└──────┬──────┘
       │
       v
┌─────────────┐
│   BullMQ    │ - upload.pdf.parse queue
└──────┬──────┘
       │
       v
┌─────────────┐
│   Worker    │ - Extracts PDF text
│             │ - Stores in database
└──────┬──────┘
       │
       v
┌─────────────┐
│ PostgreSQL  │ - uploads, upload_files,
│             │   upload_parse_runs tables
└─────────────┘

┌─────────────┐
│   Monitor   │ - Collects metrics every 5s
└─────────────┘ - Saves to CSV
```
